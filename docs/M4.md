# M4：用户代码怎样受控进入内核

前提是 M3 的真实抢占已通过，包括保存帧故意损坏的反例。现在把固定地址链接的 freestanding 用户 C 程序放进只读可执行页，经 `iretq` 进入 CPL3。两个 task 暂时共享一个下半部地址空间，各有独立用户栈；这里仍不宣称进程隔离。

采用最直观的 `int 0x80`：DPL3 的中断门允许这一入口，TSS.RSP0 提供当前 task 的内核栈；入口保留现场，C 按 RAX 分派，RDI/RSI/RDX 传参，RAX 返回。不是 Linux ABI，也不实现复杂快速 syscall 入口。

先只提供 task 编号、串口字节写出、时钟计数、实验报告和退出。用户缓冲区必须是当前根中可访问的用户页，检查溢出、跨页和长度上限后才访问；未知调用和非法指针返回错误。程序在用户态实际计算并经历抢占，然后一个主动访问内核页产生用户保护异常，另一个能继续退出。内核收到意外异常则失败，不能把任意崩溃算作“隔离成功”。

通过条件：GDB 看到低地址用户 RIP、CS=0x23，syscall 的保存帧来自 CPL3；调用返回并被用户程序验证；两个 task 均被时钟打断；指定内核页读取出现向量 14、CR2 与用户保护错误码，故障只终止该 task，另一个完成。ELF 不链接 libc 或第三方运行库。程序映像固定链接后嵌入，暂不做 ELF 文件加载器或动态链接。

## 实际结果

64/256 MiB 与 GDB 通过，命令 `tools/stage.ps1 -Milestone M4`。保存帧来自 CS=0x23；用户实际核对正常写出、未知调用与三种非法缓冲区的返回值。对 `0xffffffff80000000` 的用户读取发生 #PF，错误码 5（present、user、read），只停止 task 0；随后 task 1 继续得到时钟并报告成功。退出后切回启动 CR3，页表与普通页全部归还，空闲计数恢复。内核与用户 ELF 的符号表都仅有空的 UND 0 项，没有未解析外部符号。

最初 [运行](evidence/m4-first-order.log)虽然各局部检查通过，但 task 1 先退出，未证明“故障之后还能运行”。现在给它更长的实际计算窗口，并在其报告入口要求 task 0 已出现指定故障；[纠正后的运行](evidence/m4-pass.log)保留故障→单 task 停止→另一个继续→退出的次序。这里补的是因果证明，不把最初绿色输出倒写成同等资格。
