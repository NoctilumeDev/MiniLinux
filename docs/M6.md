# M6：什么时候可以把两个 task 称为 process

M5 已把用户程序→受控入口→文件字节→用户核对与输出串起来。M6 额外证明地址空间隔离：两个根页表各自映射代码、数据、用户栈；数据使用同一个虚拟地址 `0x600000`，物理页不同。每个程序写自己的标记并在时钟轮转后反复核对，同时增长自己的计数。内核经 HHDM 独立读回两页，核对两个根、两个物理页、两个标记和非零计数。

保留单核数组轮转。内核映射是两者共享的 supervisor 上半部；数据与用户栈可写且 NX，代码只读且可执行。内核栈仍是每个 task 的独立固定数组。没有 fork、COW、共享页、动态链接或 POSIX 兼容声明。

四次客体实验分别让一个程序在完成文件核对与报告后读取内核页、写只读代码页、执行 NX 数据页、读取未映射地址。每次必须核对指定 CR2、CPL3 与 #PF 错误码；另一个程序在故障之后继续计算、报告并退出。任意其他异常不是通过。

再用 GDB 故意把第二个空间的数据映射指向第一个的物理页。两个用户栈仍独立，用户标记检查应拒绝这份错误的“隔离”，不能依靠内核先做静态比较才发现。最后回到正常映像复验。只有这些事实与同机精确提交干净克隆成立，才升级 process 的声明；GitHub 发布状态仍另行记录。
