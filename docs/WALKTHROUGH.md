# 顺着一个用户程序读 MiniLinux

我们要回答的是：一个程序怎样拿到内存与 CPU 时间，再经内核入口读到文件里的字节？下面按真实运行顺序读代码。看懂这一条链比记住模块名字更重要。

## 先进入 C

`kernel/main.c` 声明 Limine 请求。启动器把 ELF 加载进内存、准备长模式与映射，再进入 `kernel_main`。COM1 输出是外部观察面；`panic` 关中断后停机。宿主脚本有时限并清理自己启动的 QEMU/GDB。我们没有实现 bootloader。

## 物理页是资源，虚拟地址是名字

`kernel/memory/page.c` 先问内存图哪些范围是 USABLE，再拿一小块 USABLE 存状态数组。保留区不是“暂时忙”，不能被 free 变成空闲。普通页只有空闲→分配→空闲这三个方向。返回值是物理地址整数；不能把它直接当作 C 指针。

`kernel/memory/vm.c` 用物理页存四级页表。CR3 指向根的物理地址；CPU 用虚拟地址的四组索引逐级查找，最后加页内偏移。HHDM 是启动器给内核的访问窗口，便于读写物理页。M2 真正切换 CR3，检查两个别名与物理页的字节，而不只打印一份“映射成功”。

地址空间拥有页表页；映射的数据页由调用者拥有。上半部借用的启动映射不归它释放。map 因资源不足失败时可能保留已经创建的空页表，它们仍被记录并在 destroy 时释放；这不是事务式全量回滚的接口。

## 时钟为什么能打断计算

`kernel/cpu.c` 建立 GDT、IDT、TSS，配置 PIT/PIC。这里明确关闭 LAPIC，支持的是固定 QEMU 单核传统中断路径。不是所有 PC 都可以照这个步骤使用。

时钟进入 `kernel/entry.S`，CPU 已留下 RIP、CS、RFLAGS、RSP、SS；入口再保存全部通用寄存器、向量与错误码。`struct interrupt_frame` 的字段顺序与它对应。汇编只负责进出这条硬件边界：调用 C，拿到 C 返回的帧指针，恢复现场并 `iretq`。

`kernel/task.c` 用长度为二的数组轮转。被中断的 task 保存当前帧，下一份帧决定恢复谁；进入下一个 task 前更换 CR3 与 TSS.RSP0。task 没有调用 yield，计数依然都增长，才是“它们都获得了 CPU 时间”的证据。

## 用户程序不是一个内核函数调用

`user/program.c` 独立编译和固定链接到 `0x400000`，构建时嵌入其字节。`kernel/user.c` 给代码、数据、用户栈分配物理页并映射，再构造 CS=0x23、SS=0x1b 的返回帧。`iretq` 后 CPU 处于 CPL3，GDB 能直接看到这个状态。

M4/M5 的两个 task 共享下半部，但各有用户栈。M6 才给它们两个根；相同的 `0x600000` 分别落到不同物理页。程序反复核对自己的标记，内核又经 HHDM 读回两页。此时才证明它们具有独立进程地址空间。当前运行的是同一内嵌程序的两个实例，不支持任意 ELF 加载。

## 一次 read 穿过哪些边界

用户的 `call` 封装 `int 0x80`，RAX 是编号，RDI/RSI/RDX 是参数。只有指定中断门允许 CPL3 发起调用；TSS.RSP0 把处理放到当前 task 的内核栈。`kernel/syscall.c` 用一个 switch 分派，最后把返回值放回保存帧的 RAX。恢复帧后，用户代码继续检查这个返回值。

`user_range` 检查整个范围的用户权限、可写要求、跨页与长度边界。它在关中断、页表不改变的期间完成；没有“先写一半，再发现后半页不合法”。返回 -2 的 read 不推进文件偏移。

`kernel/ramfs.c` 中的文件是名字、字节、长度；每次 open 在当前 task 的两个槽里记录文件与自己的偏移。read 取 `min(请求长度, 剩余长度)`，复制后才推进偏移，EOF 返回 0。用户以 5+12 字节读出文件，逐字节核对，最后经 write 输出返回的内容。

## 为什么要故意弄坏它

`SYS_REPORT` 是实验观察入口，`SYS_TICKS` 是演示计时入口；它们不属于 POSIX，也不是面向不可信程序的通用验收服务。实验程序只在自己的检查通过后报告，内核同时核对真实入口、抢占、读取计数、保护异常和回收。

用户读取内核页、改写代码、执行数据、访问未映射地址，分别触发指定的 #PF。只终止故障程序，另一个还要继续运行。GDB 再故意破坏保存寄存器或把两份数据页映射成同一页，正常闭环必须拒绝它们。反例没真的注入成功就不算验证。

最终的 intentional stop 是实验完成后的明确停机点。没有 shell、GUI、网络、磁盘、SMP 或生产安全承诺。核心程序没有 libc 或第三方运行库；构建和观察工具依然有明确依赖。读每轮文档看证据范围，读代码看机制怎样成立。
