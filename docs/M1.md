# M1：一页物理内存为什么可以分配

本轮从 `main@5e459b0e3f22a59924e78202ea5e331071c56e27` 开始。M0 工具、BIOS 启动、镜像载荷校验、串口和 GDB 继续复用；M0 标签不移动。

## 开工前的定义

唯一的问题是：内核怎样根据启动内存图，把一页可用物理内存交出去，并在合法释放后再次使用它？本轮做到单核、4 KiB 页的分配和释放就停。自己的页表、堆、时钟、task 和用户态仍属后续里程碑。

输入是固定版本 Limine 的 Memory Map 与 HHDM 响应。内存图给出物理地址范围；CPU 访问这些页时使用 `HHDM offset + physical address`。HHDM 偏移必须读取，不写死。M1 借用启动器已建立的映射，不据此宣称 M2 已完成。

只把 `USABLE` 区域交给分配器。内核、模块、bootloader-reclaimable、ACPI、设备及其他保留区不进入空闲池。零号页在本轮主动保留；分配结果用布尔值表示成功，物理地址通过输出参数返回。

分配器的状态只有一个所有者，用普通字节数组表达三种状态：

```text
不参与分配
空闲 → 已分配 → 空闲
```

“不参与分配”不能通过释放变成空闲。“已占用”不能同时代指保留页和分配出去的页。状态数组自身从一个足够大的 USABLE 区域取得，并把覆盖的整页排除；获取这块元数据发生在普通分配接口启用之前。数组大小依据最高 USABLE 页计算，不让高地址 MMIO 保留区撑大元数据。

实现先用直观的扫描和循环，不做 buddy、slab、SMP 或通用 allocator 框架。256 MiB 客体中，每页一个状态字节约需 64 KiB 元数据；这部分属于客体内存。

## 预期与反例

同一份核心代码在 QEMU 的 64 MiB 和 256 MiB 客体中运行。验证顺序固定为：

1. 读取真实内存图与 HHDM，初始化状态和元数据保留区。
2. 分配两个不同、对齐且属于 USABLE 的物理页，经 HHDM 写入不同内容并读回。
3. 尝试释放零号页、元数据页、bootloader-reclaimable 页、未对齐地址和越界地址；均拒绝，空闲数不变。
4. 无释放地继续分配直到耗尽，核对地址递增、所属范围、总数和有界失败。扫描从低页开始，未发生释放时按地址递增分配。
5. 耗尽后只释放一个页：重复释放拒绝，再分配只能取得这一页；原来两个页的字节仍可读回。
6. 归还本次实验分配的所有页，空闲数恢复，之后仍能再次分配和释放。

串口保存分配地址、内存图类型、HHDM、元数据范围、计数和检查结果；GDB 在入口、第一次分配和预期停止处观察。正常输出只能证明实际走过的路径；失败仍由脚本有界退出和清理，不用延长超时掩盖机制问题。

任一页重复分配、越过 USABLE 范围、保留页释放被接受、元数据被重新分配、计数或内容不一致、镜像载荷不匹配、超时或干净克隆无法重跑，都停止宣称 M1 通过。首个失败保留，再区分代码、启动协议、镜像或工具问题。

## 从别人的错题中保留什么

- [Quin 的修复提交](https://github.com/InboraStudio/Quin-Kernel-Template/commit/80733b3960fd75c97fb76b58409e28263a1542db)记录了高地址 MMIO 撑大位图和旧 ISO 隐藏新代码问题。M0 的独立载荷校验继续保留。
- 该提交的 [释放代码](https://github.com/InboraStudio/Quin-Kernel-Template/blob/80733b3960fd75c97fb76b58409e28263a1542db/kernel/mm/pmm.c)把保留与已分配都编码成置位。按源码推导，`free(0)` 能释放主动保留的零号页；未在对方系统实跑。这里把它转成我们自己的反例。
- [minios 的修复](https://github.com/kunihiko-t/minios/commit/e84f4644ba89094f3bb64d84ab31a64642f39130)去掉 allocator 的复制能力，避免两份状态管理同一批物理页。这里保持一个状态所有者。
- [固定版本协议](https://github.com/Limine-Bootloader/limine-protocol/blob/da65184e91f80fcb397270121b1e2515a11e01ee/PROTOCOL.md)保证 USABLE 区域的起点与长度按 4096 字节对齐，也明确响应和启动页表可能处于 bootloader-reclaimable 区域。当前不回收它们。

这些来源用于学习失败机制。实现由本轮问题推导，不复制外部内核代码。

## 本轮资源与当前状态

开工前本机可用内存约 4.4 GiB。构建、单个 QEMU、GDB 串行运行；客体固定为单核、最多 256 MiB。先按额外约 1 GiB 留宿主预算，这是估计，不能当作实测峰值。
