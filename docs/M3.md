# M3：两个 task 为什么都能获得 CPU 时间

开工前的条件：M2 的真实 CR3 与地址读回已通过。继续只称 task，暂不宣称用户边界或进程隔离。

一个 task 是执行上下文和自己的内核栈。两个 task 各自只做计算，不主动 yield；PIT 产生时钟 IRQ，PIC 转到 IDT 的 32 号向量，入口保存通用寄存器与 CPU 返回帧，C 选择下一份帧，汇编恢复后 `iretq`。使用简单数组轮转，每个 task 必须多次获得时钟片段并持续增长自己的计数；任务中的固定寄存器值跨抢占不得损坏。

GDT/IDT、必要的 TSS 结构与入口汇编属于 CPU 边界。主体调度仍是普通 C。串口每次显示切换来源、去向、计数；记录是真实中断发生后的观察，不在内核里假造两份输出。时钟门关闭 IF，调度和串口在关中断期间完成；不做锁、优先级或多核。

成功需两者都执行、被时钟打断并恢复，CPU 帧布局与 C 结构对齐，异常能保留向量/错误码/RIP。只有时钟次数增长而任务计数不增长、寄存器损坏、异常或超时，均不得通过。

[Intel 手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)核对长模式中断的 SS/RSP 与 `iretq` 布局；[xv6 教材](https://pdos.csail.mit.edu/6.828/2025/xv6/book-riscv-rev5.pdf)用于对照时钟为什么触发调度，不照搬 RISC-V 入口。这里只支持 QEMU PC 的 8259 PIC/8254 PIT。
