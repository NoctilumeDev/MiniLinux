# M2：地址怎样落到一页物理内存

从 M1 本机候选 `36ab4e5` 继续。用户已授权按既有 M2–M6 顺序完成教学闭环；这不把尚未运行的模块提前记成通过。

## 先定义证明

M2 创建自己的四级页表根。上半部保留 Limine 的内核和 HHDM 映射，并把根入口限制为 supervisor；下半部由我们管理。不回收启动器页表，不重造启动器。四级分页是本轮条件；若 CR4.LA57 开启则拒绝。

把同一个物理页映射到两个低地址，经第一个虚拟地址写入，再经第二个虚拟地址与 HHDM 读回。实际装载新 CR3，不能只在数组里模拟地址换算。重复映射、未对齐、越界地址必须拒绝；取消映射后页表查询应失败，重新映射到另一个物理页后应读到新内容。取消映射刷新当前根的 TLB。

页表页由 M1 分配器提供，每个地址空间用一个小数组记录自己拥有的页表页；映射的普通数据页仍由调用者拥有。销毁只允许用于非当前根，释放自己的页表，不释放借用的上半部或普通数据页。本轮不做共享页引用计数、COW、按需分页、大页或 SMP。

成功条件是：真实 CR3/虚拟写入/物理读回一致，反例拒绝，切回启动根后销毁实验空间和数据页，空闲计数恢复。非法地址真正触发 CPU 异常留到中断入口就绪以后验证。

## 阅读依据

[Intel 软件开发手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)用于核对 CR3、四级分页、U/S、R/W、NX 与 TLB 规则；[固定 Limine 协议](https://github.com/Limine-Bootloader/limine-protocol/blob/da65184e91f80fcb397270121b1e2515a11e01ee/PROTOCOL.md)决定哪些启动映射和内存仍被借用。实现不复制 Linux 或 xv6 的分页代码。

## 零依赖的准确范围

内核和用户程序是 freestanding C，不链接 libc、第三方运行库或现成内核组件。编译器自带的整数类型头文件属于编译环境。Clang/LLD、Limine、QEMU/GDB，以及宿主制作 ISO 的 Python/pycdlib 是实验工具，仍列明版本；整个实验工具链不能称作没有依赖。
